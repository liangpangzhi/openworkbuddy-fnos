# 04 · 踩坑记录

本次在一台 fnOS（192.168.5.11:5667）上实战打包、安装时踩到的坑，按"会不会卡死"排序。

## 1. Windows 下 fnpack 打的包，生命周期脚本没有可执行位

**现象**：安装过程中报权限错误，脚本根本没跑起来。
**原因**：fnpack 在 Windows 上把 `cmd/*` 打成 `0666`，Linux 下执行不了。
**解决**：打包后重写外层 tar（`scripts/build_fpk.py`），把 `cmd/*`、`*.sh` 设成 `0755`。

## 2. 第三方包不能用 `run-as: root`

**现象**：`install/info` 返回 `10150`，响应体 `data.userGroupInfo.userName=root`。
**解决**：`config/privilege` 用 `"run-as": "package"`（官方文档里 root 只给官方合作开发者）。
所以「安装时导入镜像」这种事只能以应用账号身份调 docker，脚本里要做失败兜底，不要 `exit 1` 阻断安装。

## 3. NAS 拉不动 docker.io

**现象**：`docker image pull node:20-bookworm-slim` 一直 `step=downloading, current=0`，
换 `docker.nju.edu.cn` 直接 `status=-1`（失败）。
**解决**：两条路一起上——

- 构建机（能连 Docker Hub）用 Registry API 把 layer 拉下来，组装成 `docker save` 格式的 tar，
  打进 FPK，安装时 `docker load -i`（`scripts/fetch_image.py`）
- compose 的 `image:` 用可达的镜像站 tag
  （`swr.cn-north-4.myhuaweicloud.com/ddn-k8s/docker.io/library/node:20-bookworm-slim`），
  作为导入失败时的在线兜底

**注意**：`docker load` 这一步如果失败，compose 会去拉镜像、在拉不动的网络里无限挂住，
表现为安装任务卡在 80% 不动。所以导入逻辑一定要加 `timeout`，且日志落到 `$TRIM_PKGVAR`。

## 4. compose 里拿不到 `${TRIM_PKGVAR}`

**现象**：照着网上的例子在 compose 里写 `${TRIM_PKGVAR}:/data`，挂载出来是空目录。
**原因**：compose 由应用中心调用，那一刻没有生命周期脚本的 `TRIM_*` 环境变量。
**解决**：用绝对路径 `/var/apps/<appname>/shares/<appname>`、`/var/apps/<appname>/target/docker/app`。
这也是官方 docker 模板的写法。

## 5. Docker 型应用的 `cmd/main` 不要自己 `compose up`

官方模板里 `start`/`stop` 就是空实现（"docker application will be started by appcenter"）。
自己在 start 里做重活（比如导入 200MB 镜像）会把安装任务拖到超时。
本项目只在 `start` 里做一个"镜像在不在"的快速兜底检查。

## 6. 同一 appname 重复安装会被卡住（10500）

**现象**：卸载后再装同一个 `appname`，`POST /app-center/v1/install/task` 一直返回

```
App Center code 10500: status operation is not supported for the app in its current state
```

`--dry-run` 却一切正常，`app list` 里也查不到该应用。
**推测**：卸载那次客户端超时了，服务端残留了一条任务记录。
**已试过且无效**：换 `--volume-id`、取消已知 taskId、等 40 分钟、改版本号。
**绕过**：换 `appname`（本项目最终用 `aiworkbuddy`）。桌面显示名仍可以是 OpenWorkBuddy。
**教训**：开发调试阶段别用"装→卸→装"循环，优先改版本号直接覆盖安装。

## 7. `npm ci` 在已存在 node_modules 的目录里会触发批量删除

**现象**：本地环境的安全策略拦截了 npm 的清理动作（`SAFE_DELETE_BULK_CONFIRM_REQUIRED`）。
**解决**：把 `package.json` + `package-lock.json` 拷到一个干净目录里 `npm ci`，再把 `node_modules` 拷回来。

## 8. 首启卡的 4 分钟是 apt

入口脚本第一次启动会试装 python3 / git / 中文字体。网络不通时 `apt-get update` 会干等超时。
**解决**：`timeout 45 apt-get update` + `timeout 240 apt-get install`，
并且**无论成功与否都写 `.sysdeps-ok`**，保证只试一次。

## 9. fnos-cli 连接自签证书的 NAS

```
--host 192.168.5.11 --port 5667 --scheme https --tls-insecure
```
不加 `--tls-insecure` 会 `invalid peer certificate: UnknownIssuer`。
OAuth 授权码 5 分钟过期，过期后要重新 `login --authorize-only` 生成链接。

## 10. 桌面入口的协议与混合内容

飞牛管理页是 HTTPS（`https://<NAS>:5667`），桌面入口如果声明 `type: iframe` + `protocol: http`，
浏览器会按混合内容直接拦掉。本项目用 `type: url`（新标签页打开），最省心。
真要在 HTTPS 页面里内嵌，得让应用监听 unix socket 并用 `gatewaySocket` 走飞牛统一网关。
