# 01 · 飞牛 FPK 打包开发文档

面向第一次做飞牛 fnOS 应用的人。以本项目（Docker 型应用）为样本，逐项说明每个文件的作用和写法。

## 1. 两种应用形态

| 形态 | 说明 | 本项目 |
| --- | --- | --- |
| 原生（native） | 可执行文件直接跑在系统里 | |
| Docker 型 | 用 `app/docker/docker-compose.yaml` 描述容器，由应用中心拉起 | ✅ |

Docker 型的关键是 `config/resource` 里声明 `docker-project`，应用中心会自己 `compose up/down`，
因此 `cmd/main` 的 `start`/`stop` 应该留空（不要自己再 `docker compose up`，会和平台抢控制权）。

## 2. 开发目录 → 安装目录

打包前（本仓库 `fpk-src/`）与安装后（`/var/apps/<appname>/`）的对应关系：

| 开发目录 | 安装后 | 环境变量 |
| --- | --- | --- |
| `app/` | `target/`（`TRIM_APPDEST`） | 可执行文件、UI 资源 |
| `cmd/` | `cmd/` | 生命周期脚本 |
| `config/` | `config/` | privilege + resource |
| `manifest` | `manifest` | 应用元信息 |
| — | `etc/ home/ var/ tmp/ meta/` | `TRIM_PKGETC` / `TRIM_PKGHOME` / `TRIM_PKGVAR` … |
| — | `shares/` | `resource.data-share` 声明的共享目录 |

`fnpack` 会把 `app/` 打成 `app.tgz` 放进 `.fpk`，`.fpk` 本身就是 tar.gz。

## 3. manifest（key=value，等号前后不要空格）

```ini
appname=aiworkbuddy                       # 唯一标识，桌面入口 key 要以它做前缀
version=0.17.5-1                          # x[.y[.z]][-build]
display_name=OpenWorkBuddy
desc=…                                    # 支持 HTML
platform=x86                              # x86 | arm | all
source=thirdparty
maintainer=… / distributor=…
service_port=3800                         # 服务端口
checkport=true                            # 启动前检查端口占用
os_min_version=0.9.0
desktop_uidir=ui                          # app/ 下的 UI 目录名
desktop_applaunchname=aiworkbuddy.main    # 必须与 app/ui/config 的 key 一致
ctl_stop=true                             # 显示启停按钮
changelog=…
```

## 4. config/privilege

```json
{
    "defaults": { "run-as": "package" },
    "username": "docker-aiworkbuddy",
    "groupname": "docker-aiworkbuddy"
}
```

- 第三方包**不能**用 `run-as: root`，应用中心会返回 `10150` 拒绝（`data.userGroupInfo.userName=root`）。
- 不指定 `username`/`groupname` 时默认用 `appname`。

## 5. config/resource

本项目同时用到两种资源类型：

```json
{
  "docker-project": {
    "projects": [ { "name": "aiworkbuddy", "path": "docker" } ]
  },
  "data-share": {
    "shares": [ { "name": "aiworkbuddy" } ]
  }
}
```

- `docker-project.path` 是相对于 `app/` 的目录，里面放 `docker-compose.yaml`。
- `data-share` 声明的目录会出现在飞牛「文件管理」里，路径是 `/var/apps/<appname>/shares/<name>`。

## 6. cmd/ 生命周期脚本

9 个脚本都必须存在，用不到就 `exit 0`：

| 脚本 | 调用时机 |
| --- | --- |
| `install_init` / `install_callback` | 安装前 / 安装文件写入后 |
| `upgrade_init` / `upgrade_callback` | 升级前 / 升级后 |
| `uninstall_init` / `uninstall_callback` | 卸载前 / 卸载后 |
| `config_init` / `config_callback` | 配置变更前 / 后 |
| `main` | `start` / `stop` / `status` |

退出码约定：`0` 成功；`1` 失败（错误信息写进 `$TRIM_TEMP_LOGFILE`，会以弹窗展示给用户）；
`status` 返回 `0` 表示运行中，`3` 表示未运行。

本项目的 `cmd/main`：

```bash
case $1 in
start)  # 容器由应用中心拉起，这里只兜底确认内置镜像已导入
        exit 0 ;;
stop)   exit 0 ;;
status) docker inspect <container> | grep -q '"Running": true' && exit 0 || exit 3 ;;
esac
```

`cmd/install_callback` 负责把内置镜像导入 Docker（`docker load -i`），这是"离线自包含"的关键一步。

> ⚠️ **Windows 上用 fnpack 打包会丢掉可执行位**（`cmd/*` 变成 0666），安装后脚本执行失败。
> `scripts/build_fpk.py` 会在 fnpack 之后重写外层 tar，把 `cmd/*` 和 `*.sh` 改成 0755。

## 7. 桌面图标（app/ui/config）

```json
{
    ".url": {
        "aiworkbuddy.main": {
            "title": "OpenWorkBuddy",
            "icon": "images/icon-{0}.png",
            "type": "url",
            "protocol": "http",
            "port": "3800",
            "url": "/",
            "allUsers": true
        }
    }
}
```

- `.url` 下的 key 必须以 `appname` 为前缀，且与 `desktop_applaunchname` 一致
- `icon` 里的 `{0}` 是尺寸占位符，需要提供 `images/icon-64.png` 和 `images/icon-256.png`
- `type`：`url` 新标签页打开；`iframe` 内嵌打开（HTTPS 页面里嵌 HTTP 会被浏览器混合内容拦截）
- `port` 是字符串，和 `service_port` 一致
- 拼接规则：`{protocol}://{当前浏览器 hostname}:{port}{url}`

根目录还需要 `ICON.PNG`（64×64）和 `ICON_256.PNG`（256×256），应用中心列表用。

## 8. docker-compose.yaml 的写法要点

```yaml
version: "3.8"
services:
  app:
    image: swr.cn-north-4.myhuaweicloud.com/ddn-k8s/docker.io/library/node:20-bookworm-slim
    container_name: aiworkbuddy
    restart: unless-stopped
    working_dir: /app
    command: ["sh", "/app/docker-entrypoint.sh"]
    environment:
      OPENWORKBUDDY_HOME: "/data"
    volumes:
      - "/var/apps/aiworkbuddy/shares/aiworkbuddy:/data"
      - "/var/apps/aiworkbuddy/target/docker/app:/app"
    ports:
      - "3800:3800"
```

**不要在这里用 `${TRIM_PKGVAR}` 之类的变量** —— compose 由应用中心调用，生命周期脚本里的
`TRIM_*` 环境变量在那一刻并不一定存在。用 `/var/apps/<appname>/...` 这种绝对路径最稳。

## 9. fnpack 用法

```bash
fnpack create <appname> --template docker     # 生成模板（推荐先看一眼官方模板）
fnpack build --directory <源目录>             # 打包，产出 <appname>.fpk
```

打包校验：`manifest` 必填字段、`config/privilege`、`config/resource`、`ICON.PNG`、`ICON_256.PNG`、
`app/`、`cmd/` 必须存在且为合法 JSON。

下载地址：<https://developer.fnnas.com/docs/cli/fnpack/>
