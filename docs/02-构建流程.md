# 02 · 构建流程：从源码到 .fpk

整体三步：组装运行目录 → 取基础镜像 → 打包。

```
上游 openworkbuddy (v0.17.5)
        │  git clone + npm ci --omit=dev
        ▼
fpk-src/app/docker/app/      ← 应用代码 + node_modules（约 365MB）
        │
        │  + docker-entrypoint.sh / docker-seed.js
        │
fpk-src/app/docker/images/node-20-bookworm-slim.tar   ← fetch_image.py（205MB）
        │
        │  fnpack build  +  修正可执行位（build_fpk.py）
        ▼
openworkbuddy-0.17.5-1.fpk   （约 160MB，可以直接分发）
```

## 前置条件

- Node.js 18+（构建机用，NAS 上不需要 —— 依赖已经打进包里）
- Python 3（构建脚本）
- `fnpack`：<https://developer.fnnas.com/docs/cli/fnpack/>，放到仓库根目录或 `PATH` 里
- 能访问 GitHub 与 Docker Hub（构建机可联网即可，NAS 全程离线）

## 步骤 1：组装容器运行目录

```bash
bash scripts/prepare-payload.sh v0.17.5
```

做的事：

1. `git clone --depth 1 --branch <tag>` 上游仓库到临时目录
2. 在干净目录里 `npm ci --omit=dev`（`ELECTRON_SKIP_BINARY_DOWNLOAD=1`，跳过桌面壳的上百 MB 二进制）
3. 把源码（排除 `.git` / `data` / `workspace` 等）拷进 `fpk-src/app/docker/app/`
4. 拷入 `node_modules`
5. 把 `docker-entrypoint.sh`、`docker-seed.js` 放回运行目录

国内网络建议加镜像：`npm ci --registry=https://registry.npmmirror.com`（脚本已带）。

## 步骤 2：取基础镜像（离线自包含的关键）

```bash
python scripts/fetch_image.py
```

直接走 Docker Hub 的 Registry API：

1. 拿匿名 token（`auth.docker.io/token`）
2. 取 manifest，若是 manifest list 就挑 `linux/amd64`
3. 逐个下 layer blob，gunzip，校验 diff_id
4. 按 `docker save` 的格式组装 tar：`manifest.json` + `<sha256>.json`（image config）+ 各层 `layer.tar`

输出 `node-20-bookworm-slim.tar`，拷到 `fpk-src/app/docker/images/` 下。
安装时 `cmd/install_callback` 用 `docker load -i` 导入，**不依赖 NAS 能不能连 Docker Hub**。

### 镜像标签的选择

本项目最终用的是：

```
swr.cn-north-4.myhuaweicloud.com/ddn-k8s/docker.io/library/node:20-bookworm-slim
```

原因：目标 NAS 直连 docker.io 拉不动，但这个华为云 SWR 的 docker.io 镜像可达。
用同一个 tag 有双重好处——

- 内置 tar 用这个 tag 导入 → 离线可用
- 万一导入失败，compose 还能从这个可达的 registry 拉（在线兜底）

要换成纯 docker.io 的 `node:20-bookworm-slim`，改 `fetch_image.py` 里的 `RepoTags`
和 `docker-compose.yaml` 的 `image:` 即可（两处必须一致）。

## 步骤 3：打包

```bash
python scripts/build_fpk.py
```

1. 调 `fnpack build --directory fpk-src`
2. 重写外层 tar：把 `cmd/*`、`*.sh` 的 mode 改成 `0755`（fnpack 在 Windows 上会打成 0666）
3. 产出 `openworkbuddy-<version>.fpk`

## 容器首次启动做了什么

`docker-entrypoint.sh`：

1. 试一次 `apt-get install python3 python3-pip git curl fonts-noto-cjk`（技能脚本要用 python，
   生成中文 Word/PPT 要字体）。带 `timeout`，失败也不影响主流程；无论成败都写
   `/data/.sysdeps-ok`，**只试一次**，后续重启不再等 apt。
2. 检查 `/app/node_modules/express`，缺失才 `npm ci` 自愈（正常情况下不会触发）。
3. 若存在 `/data/ai.env`（安装向导填的模型信息），生成 `config.json` 的 models 段。
4. `exec node server.js`

首启实测约 4 分钟（卡在 apt），之后重启是秒起。

## 版本号

`manifest` 里的 `version` 决定升级识别；飞牛应用中心对同一 `appname` 重复安装比较敏感
（见 `04-踩坑记录.md`），调试时建议用 `x.y.z-N` 的 build 后缀区分。
